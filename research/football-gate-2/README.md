## Agreed workflow

1. Follow the [procedure](procedure.md) to investigate people's experiences without
   assuming a football product. Record firsthand evidence and counterevidence.
2. Review the emerging problem statements. Identify what is supported and what
   needs more evidence; user reviews any Gate 2 approval recommendation.
3. Translate the selected supported problem into intended users, activities,
   outputs and required data/use permissions. Map each requirement back to Gate 2
   evidence IDs; do not treat every complaint as a product requirement.
4. Return to Gate 1 using that scope. Reuse the existing supplier evidence, check
   freshness and close only relevant availability/rights gaps. Record unresolved
   blockers or no-go findings honestly.
5. Once the Gate 1 work is complete and reviewed, prepare its integration into
   main, preserving the Gate 2 evidence it relies on and all source lineage.
   This is a future integration plan, not a merge or gate approval performed now.

Gate 2 provides evidence of problems, not commercial data rights or buyer proof.
Gate 3 remains a separate individual/small-operator buyer assessment. Discovery
remains blocked until all required gate approvals match the resulting scope.
